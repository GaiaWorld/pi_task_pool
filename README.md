# pi_task_pool

提供 **21 个串行分组**与 **5 档并发队列**的 Rust 任务池。负责接收、选择和交接任务，线程管理与任务执行由调用方实现。

## 安装

```toml
[dependencies]
pi_task_pool = "0.2.0"
```

Rust 2021；生产依赖为 Crossbeam 队列与缓存行填充工具。

## 基本用法

下面关闭快速交接，由调用方取出并处理全部排队任务。相同示例也位于 crate 文档中，受文档测试验证。

```rust
use pi_task_pool::{SerialQueueIndex, TaskExecutor, TaskHandle, TaskPool, TaskWeight};

struct QueuedOnly;
impl TaskExecutor<String> for QueuedOnly {
    fn fast_path_threshold(&self) -> usize { 0 }
    fn is_idle(&self) -> bool { false }
    fn try_execute(&self, task: TaskHandle<String, Self>)
        -> Result<(), TaskHandle<String, Self>> { Err(task) }
}

let pool = TaskPool::new(QueuedOnly);
let group = SerialQueueIndex::new(0).expect("合法串行组");
pool.push_serial("串行任务".into(), group);
pool.push_parallel("并发任务".into(), TaskWeight::High);
// 示例固定输入；实际概率调度应由调用方提供覆盖整个 u64 范围的随机数。
while let Some(mut task) = pool.pop(0) {
    task.push_str("：已处理");
    // 实际完成后释放句柄，允许同组的下一个串行任务被获取。
    drop(task);
}
```

池中有任务不代表当前一定能取到：例如唯一的串行组仍被其他句柄占用时，`pop` 可以返回 `None`。实际工作线程应由外部调度或唤醒机制决定何时再次获取，不能把一次 `None` 当作全局工作完成。

## 公开 API

| 类型 / 方法 | 用途与约束 |
|---|---|
| `TaskPool::new(executor)` | 创建空池，返回 `&'static TaskPool`；执行器移入池；要求任务 `Send + 'static`、执行器 `Send + Sync + 'static` |
| `SerialQueueIndex::new(index)` | `const fn`；接受 0 至 20，返回 `Some`，其余返回 `None` |
| `SerialQueueIndex::get()` | 返回校验后的 `usize` 索引，可用于常量求值 |
| `pool.push_serial(task, index)` | 提交串行任务；同组提交调用必须有序且不重叠；返回不表示任务已经完成 |
| `pool.push_parallel(task, weight)` | 提交指定档位任务；同档多个任务可同时执行 |
| `pool.pop(random)` | 从排队候选中选择唯一句柄；输入为调用方提供的 `u64` 随机数 |
| `TaskHandle` | 不可克隆；通过 `Deref/DerefMut` 访问任务；Drop 析构任务并释放串行占用，不会自动执行任务 |
| `TaskExecutor<T>` | 外部执行器协议，三个回调见下节 |

`TaskHandle` 在任务和执行器满足相应约束时可以跨线程移动：`Send` 要求 `T: Send`、`TE: Send + Sync`；`Sync` 还要求 `T: Sync`。

## 串行与并发

- 串行任务按所属分组依次获取。同组前一个句柄释放前，后一个任务不可获取；不同组可并发。
- 调用方必须保证同一串行组的 `push_serial` 调用不重叠。不同组之间、并发任务之间允许并发提交。
- 串行快速交接同样持有组占用，不能越过本组已经排队的任务。
- 任务可以是数据或闭包，但池不会主动调用它；执行逻辑由执行器或取出句柄的工作线程负责。
- 异步任务须持有句柄直到实际完成，不能在仅启动异步工作后就释放句柄。

## 排队任务的权重概率

| 并发档位 | 单位数量提示权重 |
|---|---:|
| `Highest` | 10000 |
| `High` | 1000 |
| `Middle` | 100 |
| `Low` | 10 |
| `Lowest` | 1 |

并发档位的有效权重为“压缩数量提示 × 档位权重”。最高档提示上限为 4095，其余为 8191；达到上限后按饱和提示参与选择，并通过恢复逻辑维持可见性。

每个未占用串行组的有效权重为 `min(ceil(n / 16), 3) × 100`，其中 `n` 为队列长度采样。占用中的串行组不参与获取选择。数量提示是近似值，并非精确实时队列长度。

`pop(random)` 将当前总权重划成候选区间，以 `random % total` 选择落点；区间顺序为串行组 0 至 20，再依次为最低至最高并发档。没有可选权重时返回 `None`。竞争或候选取空后重新选择，复用原始随机输入。

固定快照、近似均匀的随机输入下，候选概率近似为其有效权重占总权重的比例；允许取模偏差。这不是严格优先级，也不保证有限等待。持续传固定随机数不保证公平性。

## 快速交接：绕过概率调度

提交时先估计全池等待量：所有串行组的数量编码之和乘以 16，再加五档并发数量提示之和（包含已占用组中的等待提示）。估计允许高估或低估。

1. 只有估计量**严格小于** `fast_path_threshold()` 才调用 `is_idle()`。
2. 空闲时尝试直接交接；串行任务还必须成功认领一个未占用、实际队列为空的分组。
3. `try_execute(handle)` 返回 `Ok(())`：执行器接受，任务**不入队**。
4. 返回 `Err(handle)`：收回未执行的原句柄，回退入队，再参与后续概率调度。

**快速交接不按权重抽签。** 最低档任务也可能先于其他档位已经排队的最高档任务执行；同一串行组内仍不能插队。权重控制的是排队候选的选择机会，不是所有任务的端到端执行比例。

| 快速接受路径 | 本任务对状态字的成功更新 |
|---|---|
| 串行 | 认领时 CAS 设置 `serial_states` 的 used 位；句柄实际完成并 Drop 时清除，共两次；竞争时 CAS 可重试 |
| 并发 | 不更新 `serial_states` 或 `parallel_states`，也不发布数量提示 |

两种路径都会读取状态字估算等待量。执行器自身进行的其他池操作不包含在上表次数中；拒绝回退还会更新入队数量提示。

若所有任务都需要经过排队后的权重选择，将快速阈值设为 **0**。

## 接入外部执行器

| 回调 | 约定 |
|---|---|
| `fast_path_threshold()` | 返回快速交接阈值，0 禁用；比较压缩估计量，而非精确任务数 |
| `is_idle()` | 瞬时空闲提示；即使返回 true，随后仍可拒绝交接 |
| `try_execute(handle)` | 接受时取得唯一句柄并返回 `Ok(())`；拒绝时通过 `Err` 交回未执行的原句柄 |

接受后可以同步处理并释放句柄，也可以将句柄移交自己的工作线程。不能执行后再返回 `Err`，不能在工作尚未完成时释放串行句柄，也不能在回调中重入同组的提交操作。

这些回调只用于提交时的快速交接；普通 `pop` 只返回句柄，不会再次调用执行器。池不会创建线程或实现唤醒机制。

串行拒绝时，内部释放守卫接管 used 位，保持占用直到任务重新入队并完成数量提示发布。正常展开时守卫也会释放占用。池不捕获外部 panic；持有句柄在正常展开中释放时，同样解除对应串行占用。

## 生命周期与并发边界

- 池使用 `Box::leak` 返回静态共享引用，可直接复制该引用跨线程使用；没有池对象 Clone 或回收 API。池、队列和执行器与进程同寿命，应复用池而非不断创建。
- 没有关闭、清空、取消、超时或自动等待所有任务完成的接口。
- 核心使用 Crossbeam `SegQueue` 和原子状态，不使用互斥锁；不承诺 wait-free。底层队列获取可能等待在途槽位写入或跨块链接，长度采样也可能重试。
- `None` 仅表示本轮无可取得候选，不保证并发时刻的精确空快照。
- 提示恢复的进展保证以所有已经开始的发布与修复最终继续并完成为前提。恢复线程暂停可能暂时隐藏某档任务，恢复后通过补报重新可见；没有额外扫描或其他线程帮助恢复机制。
- 正常释放任务句柄会析构其中的任务；池本身不会最终析构仍在队列中的任务。
