# 决定与可行性

## 当前选择及理由

- Rust2021；生产依赖crossbeam-queue0.3、crossbeam-utils0.8，版本以Cargo.lock为准，当前队列0.3.14。复用队列存储，自行实现调度与串行交接；不引入完整线程运行时。
- 串行[SegQueue<T>;21]、并发[SegQueue<T>;5]，取消独立AtomicU64计数及预留/扣减/半范围保护，避免重复记账和每次提交/获取额外RMW。性能收益尚未量化，不声称更快。
- 数量恢复直接采样SegQueue::len()。其每轮tail/head/tail三次SeqCst读取，tail变化则重试；不遍历队列，但不保证固定三次读。可能包含尚未完成写入的位置，不包含已被出队认领的位置；静止时等于队列等待量。
- serial_states每队列3位：1位used、2位min(ceil(len/16),3)，21组，bit63=0。parallel_states从低到高最低/低/中/高各13位，最高12位。串行平均量已删除。
- pop(random:u64)由调用方提供随机数，对当前总权重取模；零权重先返回，重试复用random。否：内部TLS随机源及严格无偏映射，因公开固定输入更便于复现且用户接受取模偏差。
- SerialQueueIndex私有字段，const new/get保障0..21；否：公开usize提交越界panic。数组内部仍正常边界检查。
- new返回静态共享引用，push_serial/push_parallel/pop要求静态接收者。复制引用替代池Clone；TaskPool直接持有状态、队列和执行器，删除TaskPoolInner及Arc。Box::leak静态池，句柄/守卫直接指向TaskPool，不做不安全的模型结束回收。

## 当前交错分析（非形式化证明）

- 提交先queue.push再发布压缩提示；没有独立计数预留。生产者队内预留位置但未写完时，len可能非零，消费者pop可等待WRITE；不能把提示非零解释为立即取出完成。
- 并发普通提示先CAS扣1再pop，饱和不盲减。普通扣零不重建；饱和/取空恢复先Acquire读状态，再采样len；下调CAS失败重新取状态及长度。
- 否：只在下调写零后复查。反例：提示饱和L，恢复采到长度L-1后暂停；提交者入队使长度L、提示同值发布；旧CAS写L-1成功，普通消费可耗尽提示遗留任务。因此每次成功下调后（含非零）都重新采样并只增补报。不得复用下调前长度。
- 补报目标max(当前提示,min(len,LIMIT))；CAS失败重读，保持其他字段。多报可由后续取空修复；实际任务唯一取出由SegQueue保证。长度排除已认领位置与旧计数语义不同，不沿用旧预留计数证明。
- 串行used独占认领至句柄释放，数量提示下调成功后也只增补报；完成只清used。同组push不重叠，快速拒绝持有used至重新入队并发布，避免插队。
- 拒绝拆解通过无分配/无回调/不panic的所有权转移建立SerialReleaseGuard。守卫属于第四切片待实现；正常在回退发布后释放，展开时承接used清理。没有计数超限回滚场景。
- 已发布任务必须完成提示发布，不能用清used代替发布。分配失败沿用分配器行为。

## 进展取舍

用户接受所有已开始的发布/修复最终继续完成。下调后暂停可让其他消费者耗尽较低提示，剩余任务暂时隐藏至恢复者补报。不增加扫描、周期探测、帮助恢复，不承诺停顿线程独立可见性或有限等待。SegQueue自身也可能等待在途写入/链接；不声称wait-free。

## Loom选型与真实边界

- cfg(loom)启用Loom0.7（锁定0.7.2），替换本库sync模块的Arc及原子类型；普通模式使用std。条件验证依赖，不改变生产队列。
- Windows默认i686 GNU不受generator0.8.11支持。已验证nightly-x86_64-pc-windows-msvc可编译、链接，RUSTFLAGS=--cfg loom；不得据此宣称模型通过。
- Crossbeam内部原子、len快照及槽位发布不被Loom跟踪。移除内部Arc后，三个既有有界模型已实际通过，原Arc leaked不再出现；模型自身不包含目标窗口命中断言，目标窗口由独立私有确定性测试覆盖。
- 生命周期解决采取去除冗余Arc而非回收静态池；不关闭Loom泄漏检查。每个模型创建自己的新静态池，不在后续模型复用；Box及队列仍有意保留内存，有界测试不等于资源回收证明。
- 验证接缝为cfg(all(test,not(loom)))私有检查点，位于下调CAS前/成功后及并发取空分支。线程局部回调插入真实生产发布操作，复用原恢复循环，断言窗口命中及状态转移，不复制算法。测试位于src/recovery_tests_inner.rs，经内部模块加载；这是本轮明确批准的测试位置/内部观察例外，不要求此类协议测试仅走公共API。生产和Loom构建无这些回调。
- 四项确定性证据：饱和同值发布穿过旧非零下调、下调后发布、串行17→16跨档遇发布、合法多报状态下取空修复。局部回调是在精确检查点串接另一个操作，非真实线程抢占证明；真实并发由公共API回归和有界Loom模型补充。
