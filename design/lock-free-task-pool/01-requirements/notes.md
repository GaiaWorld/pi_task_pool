# lock-free-task-pool · 非功能 / 未决 / 澄清（L1）

## 非功能

- 支持多线程无互斥锁提交与获取任务。用户明确接受所有已开始的发布/修复最终继续并完成这一进展前提；恢复者暂停时该档任务可暂时隐藏，不承诺停顿线程独立可见性，不增加扫描/帮助兜底。尚无吞吐、延迟数值目标。

## 澄清记录

- 用户批准SerialQueueIndex私有字段新类型：const fn new(usize)->Option<Self>仅接受0..21，const fn get()->usize返回合法索引；push_serial只接收SerialQueueIndex。替代此前公开提交接受usize且越界panic的约定；内部数组保留正常边界检查。已有测试参数迁移仍交实现阶段。

- 接口返工：用户确认pop(random: u64)，接受整个u64范围；每次按当前总权重取模，零总权重直接返回None；竞争及候选排除后沿用原random。调用方负责随机性，允许轻微取模偏差，替代此前内部随机源及严格无偏承诺。
- 当前已落公开pop签名及内部参数转接，cargo check通过。已有测试的无参pop调用尚需在实现流程迁移；指定恢复交错的确定性验证接缝尚未设计完成，第三切片仍阻塞，旧L9不适用于本轮。

- L7 用户进一步明确：同一串行队列的插入调用不会并发，由调用方保证 push_serial 不重叠；不同队列可以并发。此前需求中并发提交按入队顺序排列，不得解释为承诺支持同一串行队列的重叠插入。获取与释放的并发边界仍按原多线程场景设计。
- 撤回未确认的串行队首保留槽建议，不增加该状态。在队列原为空、同队列插入不重叠、串行占用持续至拒绝恢复完成的前提下，回退可重新入队而不会被同队列后续插入超越。

- 用户确认：池与进程同寿命，运行期间不销毁，裸指针始终有效；不提供关闭、清空、取消或超时功能。
- 用户最终修订：21 个串行队列，序号 0..21（替代最初64个及中间32个方案）；非法序号 panic；五档优先级保持现有定义。
- 用户确认：获取非阻塞，无可获取任务（包括仅有占用中的串行队列）返回空；并发期间空返回不承诺全局精确空快照。
- 用户确认：工作线程与执行由外部负责，池不捕获任务 panic，正常展开释放句柄解除串行占用。
- 用户确认：沿用 Rust 与现有 Crossbeam 依赖；不引入新依赖，不设虚构性能指标。

- 用户确认：fast_path_threshold（原称max）比较全池近似等待量，压缩估计允许高估或低估；公式见源码，不以真实数量强制判断分支。
- 用户确认：串行任务按提交入队顺序获取，句柄释放视为完成并允许同队列下一任务获取；快速执行不得越过已有任务；执行器持有句柄至实际执行完成。
- 用户确认：接受概率调度，权重为 10000/1000/100/10/1，串行队列按中档参与；任务量可用估计值；提示可见的可执行档位有非零机会（提示恢复依赖已确认的最终继续前提），不承诺有限等待。

- 用户确认：少于 max 时检查空闲并尝试快速执行；达到或超过 max 时只入队。
- 用户确认：执行器拒绝时交回原任务，任务池回退入队，避免任务丢失。当前消费句柄且仅返回普通错误的签名不足以满足该行为，接口调整留待详细设计确认。
