# lock-free-task-pool · 需求条目（L1）

| 需求 | 验收标准 |
|---|---|
| 串行提交 | 分组为 0–20；单线程按 A、B 顺序提交，同组获取顺序为 A、B；不同组允许并发提交；同组push调用有序且不重叠；非法分组在索引构造时拒绝，不能作为合法提交参数 |
| 同组串行 | A 句柄存活时，任何工作线程均不能取得同组 B；释放 A 后 B 可获取；其他组不受阻塞 |
| 并发任务 | 支持最高/高/中/低/最低五档；取得同档 A 后不必等待 A 完成即可取得 B |
| 概率优先级 | 五档权重 10000/1000/100/10/1，串行按中档参与；选择概率受待调度量与权重影响，可用估计量；提示可见的可执行档位保持非零机会，不要求有限等待保证；档位可见性恢复以所有已开始的发布和修复最终继续并完成为前提 |
| 快速执行 | 按已约定的近似等待量与快速交接阈值比较，严格少于才检查空闲并尝试交接；达到阈值只入队；估计允许高估和低估，不以真实等待量判定阈值分支；同组快速任务不得越过既有任务 |
| 拒绝回退 | 执行器拒绝须交回原任务并回退入队；拒绝本身不得使任务丢失、重复或永久占用串行组 |
| 空返回 | 无可获取任务时非阻塞返回空；仅有占用中串行组时可返回空；并发期间不承诺精确空快照 |
| 完成释放 | 执行器持有句柄到实际完成；释放解除对应串行占用；任务 panic 的正常展开也应释放占用 |
| 并发一致性 | 多线程提交与获取保持任务不重复、不丢失，同组无重叠执行；以并发检查与后续实现测试验证 |

概率区间、阈值估计公式与并发观察验收以src/task_pool_inner.rs及07-design/call-chain.md为准；不承诺虚构吞吐指标。恢复线程可暂停，任务提示可能暂时隐藏；本次不增加扫描/帮助兜底，不保证暂停线程不恢复时仍能取尽任务。
